**E. Decisions taken from these tables (for the routing table of slice 11):**
1. **Many-call tasks (claims, scan, trace) use only Google (Flash-Lite and Gemma) and, for claims, the small Mistral models.** Any gateway with a one-at-a-time, 5-a-minute or in-flight rule cannot take 4 to 20 calls at once.
2. **Big-input tasks (audit, method, concept, checklist audit, skeptic) use only models with a large window and no per-minute input cap:** LiteRouter, Kilo, Gemini 3.6 Flash, with Flash-Lite as backup. Gemma cannot take them (16K).
3. **Gemma 26B is first for every task with an input under about 13K** (planner, summary, gate, rewrite, fresh statement, claims, trace, judge, merge, checklist), which saves Flash-Lite's 3,000 a day for the big-input jobs. Gemma 31B is only overflow. **This needs the room spreader (D70) first:** today parallel Gemma calls collide in one room, get 429, and the chain retries the same tier. So the spreader is the first piece of slice 11.
4. **Respond has three routes chosen by the plan, not by the words of the question:** chat (no files) an easy-to-medium fast chain (Flash-Lite, Gemma, Ling); one file (`ONE_FILE`, `REFERENCE`) a medium chain; two files the strongest chain, the only place for Gemini 3.6 and 3.8 Flash. A question like "what is a learning rate" must not spend a 20-a-day model.
