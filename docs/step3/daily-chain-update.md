### 32. THE DAILY UPDATE OF THE CHAIN AND THE ROUTES — an idea of the user, 2026-11-18, for the END of Step 3

*Talked through with the user on 2026-11-18. Nothing is built. It belongs at the end of Step 3 (deployment), where Airflow, the offline job runner of this file, is planned (Architecture and Stack).*

**The problem.** Providers change their free lists often. LiteRouter changes them almost every week (nine tiers left its free list on 2026-11-15, models were renamed, new ids appeared), Google changes them less. Today a person reads the lists, probes each model and edits `registry.py` by hand. That does not scale, and a stale id costs a failed call on every request.

**The idea.** A script runs once a day, updates the model ids and the alive or dead state of the chain and the routes, and opens a pull request. The order of the models in the routes must NOT be damaged by it.

| # | decision |
|---|---|
| **D117** | **The routes name FAMILIES, not provider ids.** A family is one model, for example "DeepSeek V4.1 Flash" (strength 5, set by a person). The registry keeps a table "family to the ids that serve it" (LiteRouter id A, Token Harbor id B, OrcaRouter id C). The daily script changes ONLY that table (a renamed id, a dead id, a back-alive id). A route keeps its order, because it names the family. A NEW family (DeepSeek V4.2) goes into a candidates file at the end of the chain as "unscored", and a person (or the score table below) gives it a place |
| **D118** | **The script reads the Artificial Analysis API directly. It does not use an MCP.** Reason: the update is a script without a person in the middle, and an MCP is a tool for an agent in a chat; it only adds a server and a model call. Facts, from web search summaries only (the pages were NOT opened and no MCP was installed): Artificial Analysis has an official free API ([data API](https://artificialanalysis.ai/data-api), [docs](https://artificialanalysis.ai/data-api/docs)), a key in the `x-api-key` header, **10 requests a day** on the free plan, the response carries the **version of the intelligence index** (so scores of two versions are never mixed), attribution is required (a byline or a link to artificialanalysis.ai), and pricing and per-benchmark scores are on the paid plan only. Two MCP servers wrap that API: [davidhariri/artificial-analysis-mcp](https://glama.ai/mcp/servers/davidhariri/artificial-analysis-mcp) (a `list_models` tool; one review calls it thin) and [aa-mcp](https://glama.ai/mcp/servers/Leev1s/aa-mcp). The LLM Benchmark MCP Server uses hardcoded scores and is out of date. The registry of this app has no MCP for it. One call for the model list is enough for the 10 a day |
| **D119** | **The score alone does not set the order.** The order uses score, speed, quota and trust together: Hydrogen is 51 and takes 29 to 117 s, Gemini 3.8 Flash is 31 and takes minutes. The script writes the score next to the family and PROPOSES a place; a person confirms it in the pull request. If the index version changes, the script says so and does not compare old and new scores |
| **D120** | **Matching names is the hard part, and it is a rule table kept by hand.** Providers and Artificial Analysis name one model differently ("Gemini 4 Hydrogen (High)", "DeepSeek V4.1 Flash 1017", "-cheap", "-stable", "-free", dated builds, vendor prefixes). The script normalizes strings (lower case, strip `:free`, `-free`, the vendor prefix, the reasoning suffix) and matches them to a family with regex rules written by a person for each family. **It refuses to guess:** an unmatched name goes to the candidates file and is never added to a route. The user: "possible, and it needs some work on strings or regex" |
| **D121** | **The daily smoke run gives the sittings of the trust rule.** One cheap call for each tier, once a day, written into a history file. "Trusted in 2 of 3 sittings" (31.19, the user's rule) is then counted by code: a tier moves into or out of `NOT_TRUSTED` in the pull request. Tiers with 20 requests a day (Gemini 3.6, 3.8 and 4 Hydrogen) are skipped by the daily run, and measured by hand |
| **D122** | **Safety rules.** The script opens a **pull request**, never a commit on `main` (this file's rule). The tests must pass in CI. A model joins only if it is free (price 0), answers the smoke test and matches an allow-list of families (for example DeepSeek, GLM, Qwen above a minimum version). The pull request lists exactly what changed. Providers with no public list (Cline, Google) need their own small reader. The daily run costs quota, so it uses one call for each tier |

**Airflow or GitHub Actions.** Airflow is heavy for the 8 GB development machine and needs a place to run every day. GitHub Actions can run the same Python script on a schedule (the repository already has the weekly smoke workflow). So the script is written first as a plain Python file, and Airflow is put around it at Step 3 if the user wants it for the portfolio. The script is the same in both.

**What it needs first:** the family table (a registry change that touches every route and `CHAIN`), a history file for the sittings, the name-matching rules, and the new tests (a route names only families, no route holds a dead id, the order of a route does not change when the table changes). Measure first how often LiteRouter really changes its list (a week of daily lists is enough) so the work is not bigger than the problem.

**Open:** the exact path of the free API endpoint (the pages disagree), whether the free plan returns every model we use, what to do when a provider drops a whole family, and who confirms a proposed place if nobody is looking at the pull request.
